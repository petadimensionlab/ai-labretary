**`n_cells` の意味 — 「1 遺伝子あたりの細胞数」であって延べ数ではない。**

**強制の仕組み**は `run_isp.py:988-989` のみである。


昼間モードでは停止しない。昼間に G2 未満の本実行を止めるのは運用ルール（`CLAUDE.md` §4）だけである。

#### (1) 移動量の補正の実装

**何をするか**: 交絡除去の二次回帰の説明変数に、**摂動による移動量の対数 `ld = log2(‖Δ‖)`** を加える。

| 版 | 説明変数 | 設計行列の列数 |
|---|---|---|
| 従来 | `lp`（元の順位の対数）、`ll`（入力長の対数）の完全二次式 | 6 |
| 本モジュール | `lp`・`ll`・**`ld`** の完全二次式 | 10 |

`design()`（`movement_correction.py:66-87`）は `ld=None` のとき 6 列、`ld` を与えると 10 列を返す。**列の並びは前半が一致する**ので、版の間で係数を直接比べられる。切り替えは `use_dnorm` 引数 1 つで行う（`_cols()`: `movement_correction.py:89-99`、`gene_stats()`: 同 `104-150`）。

`_cols()` は `use_dnorm=True` のとき次の 2 つで止まる。

- `dnorm` 列が無い → `KeyError`
- 移動量が 0 以下の細胞がある → `ValueError`（対数が取れない）

**導入の根拠となった実測**（EXP-20260929-001 / validation.md §2.5(a)）: 恒常発現遺伝子の移動量 ‖Δ‖ の中央値は対照 500 個の中で ACTB 99.8 パーセンタイル、GAPDH 98.6、PPIA 97.8。主指標と移動量の順位相関が +0.171 残っていた。

### 2.4 `scripts/analysis/bias_budget.py`（新規・428 行）

#### 歪みの予算の実装

**何をするか**: セット（遺伝子の集まり）の平均 z を判定に使うとき、そのセットが交絡の候補について対照から偏っていると、**中身が完全に中立でもセット平均 z がずれる**。そのずれを標準偏差の単位で直接見積もる。

```
交絡の候補 v ごとに
    b_v = （対照だけで測った「z と v の対照内分位」の傾き） × （セットの v の平均分位 − 0.5）
歪みの合計 B = Σ_v b_v
```

**定数**:

| 定数 | 値 | 行 | 意味 |
|---|---|---|---|
| `DECISION_LINE` | 0.41 | `bias_budget.py:69` | 守りたい判断（セットの絶対値条件、標準偏差の単位） |

**同時回帰と周辺回帰の両方を出す。** `_fit()`（`bias_budget.py:113-124`）は対照だけで同時回帰（5 変数の重回帰）と周辺回帰（1 変数ずつ）の両方を当て、`{"beta_joint", "cov_joint", "marginal", "n"}` を返す。`bias_budget()`（`bias_budget.py:127-184`）の返り値は次を含む。

|---|---|
| **症状** | 較正の傾きの信頼区間が実際より狭く出る。 |
| **原因** | **同じ分け方（split）から作られた行どうしが相関している。** 行を無作為に取り直す素朴なブートストラップはこの相関を無視するので、区間を狭く見せる。記録されている実測では、行のブートストラップの区間が **0.658〜0.752** と狭く出たのに対し、**分け方を変えると傾きが 0.50〜0.71 と動いた**。 |
| **修正** | **分け方ごとに傾きを出し、そのばらつきで区間を作る**（`experiments/EXP-20261002-001/analysis/validate_bias_budget_006.py:177-187`）。<br>`per = np.array([float(np.polyfit(g.est, g.act, 1)[0]) for _, g in d.groupby("split")])`<br>`sd_sl = float(per.std(ddof=1) / np.sqrt(len(per)))` |
| **実測（最終版の出力）** | 対照 250 個で傾きを当て、20 通りの分け方 × 160 セット × 3 seed = 3,200 セットを予測。観測の傾き **0.638**、分け方のばらつきから作った 95% 区間 **0.479〜0.798**。見積もり自身の雑音による希釈 0.724 を戻した傾き **0.882**（95% 区間 **0.661〜1.102**、**1.0 を含む**）。20 通りの分け方ごとの傾きは −0.015 から 1.576 まで散らばっている。信頼区間の被覆率 0.919（目標 0.95）。出力: `experiments/EXP-20261002-001/work/bias_budget_validation_006.json` |
| **日付** | 2026-10-02 |

### 4.3 解析的な標準誤差は本当のばらつきを過小に見積もる

| 項目 | 内容 |
|---|---|
| **症状** | 「対照を増やせば区間が縮んで通る」という見通しが楽観的すぎた。 |
| **原因** | 歪みの予算の解析的な標準誤差 `se_B`（`bias_budget.py:155` `se_B = sqrt(dq @ cov_joint @ dq)`）は、**対照で当てた傾き β の不確かさしか数えていない**。実際には対照プールが入れ替わると、**z の標準化も、分位の目盛りも、残差 `D_raw` そのものも動く**。これらが式に入っていない。 |
| **実測** | 既存 500 個からの部分抽出（7 サイズ × 3 seed × 200 回）で、`se_B` は実際のばらつきを **平均 1.28 倍**過小に見積もっていた。seed ごとの内訳は seed81 1.20 / seed82 **1.34（最悪）** / seed83 1.31。 |
| **対処** | **判定は事前登録どおり解析式の `se_B` で行う**（結果を見てから検定統計量を変えない）。ただし「**対照を何個にするか**」の計画の見積もりには実測の 1.28 倍を使い、計画を甘くしない。記載: `experiments/EXP-20261002-002/plan.md` §3.2(a)。 |
| **あわせて記録すべき 3 つ** | 精度を上げる提案には必ず (a) 解析式と実測の比、(b) 推定値自体の移動量（追加 500 個で SD 0.027）、(c) 頭打ちの水準（無限に増やしても合格確率 0.92）を添える。 |
| **日付** | 2026-10-02 |

### 4.4 最小検出可能効果量（minimum detectable effect）を `4.5/√K` で見積もらない

| 項目 | 内容 |
|---|---|
| **症状** | 計画に書いた最小検出可能効果量が、事前登録した判定規則での実際の値と大きく食い違った。 |
| **原因** | `4.5/√K`（K は陽性対照の遺伝子数）という粗い式は、**遺伝子間のばらつき**と **seed 間の相関**を数えていない。EXP-20260930-001 では遺伝子間のばらつき tau = 2.05、seed 間相関 0.944 が効いていた。 |
| **実測の食い違い** | 主予測 T1（**K = 11**）: 粗い式 **1.36** に対し実際の最小検出可能効果量 **2.00**。健全性チェックの陽性対照（K = 39）: 粗い式 0.69 に対し **1.03**。いずれも粗い式のほうが楽観的だった。 |
| **修正** | **事前登録した判定規則そのものをシミュレートして出す。** 実験ごとの `analysis/power_*.py` で実装している（`experiments/EXP-20260930-001/analysis/power_004.py` ほか、6 実験分）。粗い式は計画段階の目安までにとどめ、PI への報告には使わない。 |
| **関連** | 同じ下限でも「どの偶然合格率に較正した規則か」で倍近く変わる（実例: 0.32 対 0.59、効果が遺伝子ごとにばらつく条件では 0.83）。**事前登録に書く下限は、事前登録する規則そのもので計算する。** |
| **日付** | 2026-09-30 |

### 4.5 bf16 と fp32

| 項目 | 内容 |
|---|---|
| **症状** | bf16 の forward だけにすると、摂動の効果量 shift の順位が fp32 と一致しない。EXP-20260925-001 の試し実行で **Spearman ρ = 0.43（n = 8）、符号一致 4/8**。素の bf16 は使えない。 |
| **原因** | shift は **≈1 のコサイン 2 つの差**（大きさ ~1e-4）である。bf16（有効桁 ~3 桁）のまま `quant_cos_sims` を計算すると、差が 2^-11 刻みに量子化されて丸めに埋もれる。 |
| **修正** | `apply_dtype()`（`run_isp.py:174-200`）が 2 つのラップを行う。<br>(a) `pu.load_model` をラップしてモデルを `torch.bfloat16` にキャストする（`run_isp.py:186-189`）— **forward は bf16 のまま**（fp32 比 ~5 倍速）。<br>(b) `pu.quant_cos_sims` をラップして**コサイン比較だけを fp32 に上げる**（`run_isp.py:191-196`）。 |
| **検証方法** | **bf16 を新しい系で使うときは、同条件の fp32 と shift の順位を比較してから採用する。** 単に速いことを理由に採用しない。 |
| **残っている制約** | この修正はコサインだけを fp32 に上げる。**分類ヘッドの logits（`capture.classifier_logits`）は bf16 のままである**（\|logit\| 4〜8 で 2^-5 = 0.031 刻み）。ΔP / Δlogit を指標にする計画では、分類ヘッドを fp32 で計算するか fp32 の対応ペアで確認し、あわせて P(goal) の分布（飽和）を事前に確認する。EXP-20260926-005 では飽和により \|ΔP\| の 99 パーセンタイルが 6e-5、Δ(logit 差) が厳密に 0 の細胞が 53% になった。 |
| **日付** | 2026-09-26（コサインの fp32 化）、2026-09-26（logits の制約を記録） |

## 5. 作業手順として固定したこと

### 5.1 事前登録の sha256 固定と、**実験ディレクトリの中から**の照合

各実験は `analysis/freeze_preregistration_NNN.sh` を持つ。実装の要点:

```bash
cd "$(dirname "$0")/.."          # 実験ディレクトリへ移動する
FILES=( plan.md config.yaml ... )
shasum -a 256 "${FILES[@]}" > work/SHA256SUMS-preregistered.txt
shasum -a 256 -c work/SHA256SUMS-preregistered.txt
```

**パスはすべて実験ディレクトリからの相対で記録される。** したがって照合も**実験ディレクトリの中から**行う。

```
shasum -a 256 -c work/SHA256SUMS-preregistered.txt
```

プロジェクトルートから走らせるとパスが解決できず、全件が落ちる。

**固定の一覧に何を入れるか**: 「判定に使う値が、どのコードのどの出力から来るか」を最後までたどり、たどった結果に登録外のコードがあれば複製して一覧に加える。**含めないもの**は理由つきでスクリプト内に明記する（試し実行・機体確認専用の設定、試し実行の出力、これから作る出力、実行時に作る `env*.json`）。

**固定の前に `run_isp.py --dry-run` を通す。** 固定してから設定の不備が出ると、そのたびに承認を記録する文書を書き換えることになる。dry-run は計算を一切しない。

### 5.2 固定後の変更は 3 点セット

事前登録を固定した後に `plan.md` や `config.yaml` を触ったら、**その場で 3 つをまとめて行う**。

1. **変更ログ**（日時・変えたこと・理由・**結果を見る前か後か**）を `plan.md` の変更ログ表に追記する
2. **承認チェックリスト**を更新する
3. **`freeze_preregistration_NNN.sh` を走らせ直し、`shasum -c` が全件一致することをその場で確認する**

固定のハッシュは中身を区別しない。承認や盲検解除の記録も「`plan.md` の変更」である。追記だけして再固定を忘れると、実行前チェックで不一致になり実験が止まる。**ファイルを編集してから `shasum -c` の全件一致を確認するまでを 1 つの作業とする。**

バージョン管理下にないプロジェクトでは、「変更したのはここだけ」は申告であって証明ではない。差分を機械的に照合できないので、**書き残していない変更は復元できない**。

### 5.3 試し実行の出力で評価コードを最後まで通してから本番に入る

| 段階 | 何を確かめるか | 確かめないこと |
|---|---|---|
| `--dry-run` | 設定に必要な項目がそろっているか（**設定の「形」だけ**） | 設定が指す先のファイルの中身 |
| 試し実行 | 状態の重心の抽出と摂動が最後まで動くか | 評価が通るか |
| **試し実行の出力に対する評価** | **評価コードが最後まで通るか** | — |

**本番の前提条件は 3 段目まで通すことである。** 2026-10-01、試し実行は摂動が走ることしか確かめておらず、評価コードは 1 度も通っていなかったため、**8.6 時間の摂動計算が終わった後**に `KeyError` で止まった（§2.2(2)）。10 遺伝子の試し実行の結果に対して評価を回していれば、8.6 時間の前に見つかった。

試し実行は `--smoke` の旗ではなく**専用の設定ファイル**で行う（理由は §2.1(3)）。判定に使う役割をすべて 1 つ以上含め、対照遺伝子は 30 個程度入れる。

### 5.4 複数 seed を回すなら、その機体の設定を全部先に送り、sha256 で照合する

**本番を始める前に、その機体が使う全ての設定の実在と sha256 をリモートで確かめる。** `isp_remote.sh push` は `CONFIG` を 1 本しか送らない（§2.6(1)）ので、2 つ目以降の seed の設定は別途送る必要がある。EXP-20261001-001 では c083 に `config-seed82.yaml` だけが送られ `config-seed83.yaml` が無かったため、引き継ぎが `FileNotFoundError` で即死した。

現在は `analysis/stage_remote_NNN.sh HOST SEED [SEED ...]` が、その機体が担当する seed の config を全部と rows ファイルを 1 回でまとめて送り、sha256 で照合する。

### 5.5 実験中に `push` を走らせない

理由は §2.6(2)。モデルへのリンクを張り替えて実行中のジョブを壊す。各実験の `plan.md` に注意書きとして入れている。

### 5.6 リモートのヒト由来データの複製は作業後に削除し、消失を確認する

```
bash scripts/remote/isp_remote.sh clean HOST
```

実装（`isp_remote.sh:94-96`）は `du -sh` で容量を表示してから `rm -rf -- $HOME/labretary-remote` し、`removed` を出力する。**出力を確認する。** 転送の確認にも同じ原則を当てる — macOS の openrsync（protocol 29）は `rsync -a` で何も転送せずに成功終了することがあるため、`-av` で送り、転送後は必ずリモートで `ls` / sha256 を確認する。小さいファイル（コード・設定）は `ssh HOST "cat > f.tmp && mv f.tmp f" < f` で書いて sha256 を照合する（`isp_remote.sh:50-54` で実装済み）。
