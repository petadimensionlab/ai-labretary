## 計算環境
- **Geneformer は Apple Silicon の MPS バックエンドでも動作する**（2026-09-25 PI 周知）。
  - 確認: `.venv` の torch 2.14.0 で `torch.backends.mps.is_available() == True`（arm64）。
  - CUDA GPU がない Mac でも smoke / 小規模 perturbation は実行可能。`config.yaml` の `compute.device` は `cuda | mps | cpu`。
  - 注意: `run_isp.py` の GPU 時間見積もりは A100 相当の値。MPS では実測で補正すること。
  - `run_isp.py` は `compute.device`（cuda|mps|cpu|auto）を読み、Geneformer の `GENEFORMER_DEVICE` 環境変数に渡す。指定デバイスが使えなければ停止（黙って切り替えない）。実使用デバイスは `results/device.json`。
  - `capture_env.sh` は `accelerators`（cuda/mps）・`cpu_model`・`config_device`・`run_device` を env.json に記録。`lab_status.sh` は Mac で MPS の可否を表示（2026-09-25 修正）。

- **精度は系ごとに matched pair で確かめてから決める**（2026-09-26 更新）。素の bf16（コサインも bf16）は不可（ρ=0.43）。bf16 forward + fp32 コサインでも**自動的に採用してよいわけではない**:
  - EXP-20260925-001 smoke（macrophage, 50 細胞 × 8 遺伝子）: fp32 比 1.49x、Spearman 0.857
  - EXP-20260926-001 phase 0c（腎 aPT, 100 細胞 × 10 遺伝子, 1 seed）: **Spearman 0.879（基準 0.98 未達）**、上位 5 一致 5/5・符号 10/10、mean|Δ| は mean|shift| の 7.0%、速度差は **1.33x だけ**。Labretary は fp32 を提案したが **PI が bf16 維持を決定**（2026-09-26）
  - **PI 方針: bf16 が標準**。基準未達でも bf16 で実行し、限界として明記＋境界付近の遺伝子だけ fp32 で確認する
  - 傾向: shift が小さい系（|shift| ~1e-4）ほど bf16 の相対誤差が効く。順位そのものを結論にする実験では fp32、上位数個の取り出しだけなら bf16 で足りる
  - 比較は `scripts/analysis/compare_precision.py`（Spearman・上位 N・ノイズ床超の符号一致・細胞単位の一致・1 細胞×1 遺伝子の秒数）
- **MPS 実測（M4 Pro, V2-316M, delete, 中央値 1,660 トークンの腎 PT 細胞）**: 1 細胞×1 遺伝子 **fp32 0.82 s / bf16 0.62 s**（`capture.embeddings: true` で埋め込みを保存すると bf16 0.68 s, EXP-20260926-002）、CLS 埋め込み抽出 0.24 s/細胞（fp32）。`compute.cache_model: true` で遺伝子ごとのモデル再ロード（1 回 30〜40 s）はなくなる。

## ドメインパターン
- **過剰発現型では恒常発現遺伝子が中立にならない。原因は摂動による移動量の大きさ**（4 実験で再現、2026-09-30 に原因特定・対策実装）。当初「上げしろが大きいから」と書き（誤り）、次に「移動量そのものが大きい」と直した。ACTB・GAPDH・PPIA の移動量は対照分布の 97.8〜99.8 パーセンタイル。**対策として、補正の回帰に移動量の対数 log2(‖Δ‖) を加えた**（`scripts/analysis/movement_correction.py`、説明変数は lp・ll・ld の完全二次式）。EXP-20260929-001 の 3 seed で検算した実測:
  - 恒常発現遺伝子 3 個のセット平均 z: **+1.071 → +0.335**、中立の範囲に入る seed 数 **0/3（不合格）→ 2/3（合格）**
  - 残差と移動量の順位相関: 0.127〜0.171 → **0.009〜0.049**
  - **主判定も動く**（分泌プログラム 24 個 +0.015 → +0.095）。補正は無害ではないので、**どの版を使うかは事前登録で固定する**
  - **目標の軸の陽性対照は 0.684 → 0.826 と近づくが、必要な 0.861〜0.896 には届かない**。補正だけでは軸は立たない（validation.md §2.5(a) は「0.718 → 0.698 でほぼ変わらない」としていたが、完全二次式で入れ直すと改善幅はもっと大きい。2026-09-30 実測で訂正）
  - 過去の検証が使った補正の実装は保存されていなかった。**感度分析のスクリプトは必ず残す。**
- **過剰発現型には「どの重心へも一様に近づく成分」がある**（2026-09-27。削除型の一様な削除効果の裏返し）。EXP-20260927-003 の対照遺伝子で、目標への接近度と別の状態（筋線維芽細胞）への接近度の相関は ρ = 0.946 / 0.913 / 0.915。**1 つの重心への接近度を主指標にすると、方向ではなく移動量の大きさを測ってしまう。** 目標に特異的な成分（目標 − 別の状態）で見ると順位が大きく変わる。

- **複数の計算機に分けるときは seed 単位で分ける**（2026-09-28）。1 台が 1 つの seed を丸ごと（全遺伝子）担当する形にする。**遺伝子で分けてはいけない** — 比較する 2 群（例: 経路セットと対照）が別の機体になると、機体差が「差がある」という結論とまったく同じ形で現れ、見分けられなくなる。seed 間の違いは、もともと繰り返しとして扱っている変動なので、seed 単位なら安全。
  - 分ける前に、同じ入力を各機体で回して埋め込みが一致するかを必ず確かめる（機体ごとにパッケージの版が違うことがある）。
- **Mac は GB10 の 3〜4.6 倍の時間がかかる**（実測: 1.2 h 対 5.5 h、6.0 h 対 18.2 h）。重い摂動を丸ごと任せると全体の足を引っ張る。**状態の重心の抽出・評価・トークン化などの補助計算に回し、摂動と並行させる**のが有効。
- **同一チップの GPU どうしなら、パッケージの版が違っても bfloat16 の計算は一致することがある**（2026-09-28 実測）。GB10 2 台（transformers 4.57 対 4.46.3）で、48 遺伝子 × 200 細胞の埋め込みと細胞ごとの指標が **sha256 までバイト同一**だった。ただしこれは確かめた結果であって前提にしてはいけない。**機体を分ける前に必ず一致確認を通す。**
