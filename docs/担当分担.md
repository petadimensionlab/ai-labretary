# 担当とモデルの分担

- 作成: Labretary / 2026-09-26（PI 指示「実行系は Sonnet、仮説設計・検証・判定の提案は上位モデル、簡単な仕事は Haiku」）
- 定義: `.claude/agents/*.md`。呼び出すときは担当名を指定する
- **どの担当も、ゲート（G1 仮説採択 / G2 計画承認 / G3 結論確定）を判断しない。** 判断は PI のみ

## 一覧

| 担当 | モデル | 仕事 |
|---|---|---|
| lab-reporter | Haiku | 進行状況の一覧（実験・仮説・実行中のジョブ・判断待ち） |
| file-verifier | Haiku | ファイルの照合（実在・大きさ・sha256・ローカルとリモートの一致） |
| artifact-refresher | Haiku | 結果閲覧ページの再生成と、同じ URL への再公開 |
| ref-checker | Haiku | PMID・DOI・アクセッションの実在確認（内容の評価はしない） |
| simulation-engineer | Sonnet | 事前登録済み計画の実行、回収、既存スクリプトでの評価 |
| literature-scout | Sonnet | 文献・公開データセットの調査（一次情報で確認） |
| report-writer | Sonnet | テンプレートに沿ったレポート作成（新しい結論は足さない） |
| hypothesis-builder | 上位 | 仮説の生成と事前登録 |
| experiment-planner | 上位 | 実験計画と判定基準の設計、計算量の見積もり |
| validator | 上位 | 批判的検証、交絡と不具合の洗い出し、判定の提案 |

## Haiku に任せない仕事と、その根拠

2026-09-26 の作業で実際に起きたことを根拠にしている。

| 任せない仕事 | 根拠になった出来事 |
|---|---|
| ゲートの判断、仮説の状態の変更 | サブエージェントが判定を `判定不能` に書き換えた（PI の判断を先取りしていた） |
| 結果が本物かの判定 | 陽性対照が恒常発現遺伝子と区別できていないことに気づく必要があった |
| もっともらしい数値の中の誤りの検出 | 対数正規化済みデータを生カウントと誤認、比の符号を見ない判定、bf16 による数値の量子化 |
| PI が読んで行動する要約 | 結論を弱める判断（否定か判定不能か）が毎回必要 |

## 使い分けの目安

1. まず担当を選ぶ。手順が決まっていて判断が要らない → Haiku。手順は決まっているが異常時の判断が要る → Sonnet。設計・判定が要る → 上位モデル
2. Haiku の担当が「判断が必要」と報告してきたら、Sonnet か上位モデルに引き継ぐ
3. 重い計算（リモート GPU）は simulation-engineer が行い、転送と照合の確認だけ file-verifier に切り出せる
